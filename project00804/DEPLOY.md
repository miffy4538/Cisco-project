# Docker化とインターネット公開について

## 1. 使い方(ローカル/LAN内)

`restart.bat` をダブルクリックするだけです。中で `docker compose up --build` が実行され、
サーバー(Node.js+Python/YOLOv8-Pose)とクライアント(React+Caddy)の両方のイメージが
自動でビルド・起動します。`npm install` や `pip install` を手動で実行する必要はもうありません。

初回はPyTorchなどのダウンロードが入るため数分かかります。起動したら、ブラウザで

```
http://localhost
```

を開いてください(ポート番号は不要です。Caddyが80番ポートで待ち受けます)。

止めるときは `restart.bat` を実行しているウィンドウで `Ctrl+C`、または

```
docker compose down
```

を実行してください。

## 2. 構成

```
System_1/
├─ docker-compose.yml   ← 全体の起動定義
├─ .env.example          ← 設定のひな形(コピーして .env として使う)
├─ server/
│   └─ Dockerfile        ← Node.js + Python(YOLOv8-Pose)のイメージ
└─ client/
    ├─ Dockerfile        ← React(Vite)をビルドし、Caddyで配信するイメージ
    └─ Caddyfile          ← Caddyの設定(静的配信 + /socket.io/ の中継 + 自動HTTPS)
```

`server` コンテナは外部に一切ポートを公開せず、`web`(Caddy)コンテナからのみアクセスできます。
ブラウザは常に1つのURL(Caddy)としか通信しないため、CORSの心配もありません。

以前の `Dockerfile` / `index.html` / `Dockerメモ`(ルート直下)は、最初にDockerの練習用に
作られたものなので、新しい構成では使われていません。残しておいても支障はないので、
不要であれば削除していただいて構いません。

## 3. インターネットへ公開する手順

見守りシステムをインターネット越しに見られるようにするには、コード側の設定に加えて、
以下のようなご自宅のネットワーク側の準備が必要です(これらはAIでは代行できない、
お客様側で行っていただく作業です)。

### (1) ドメイン名を用意する

- 独自ドメインを取得する、または無料のダイナミックDNSサービス(例: DDNS系サービス)を使う。
- ドメインのDNS Aレコードを、ご自宅のグローバルIPアドレスに向ける。
  (固定IPでない場合はダイナミックDNSクライアントで自動更新する仕組みが必要です)

### (2) ルーターのポート開放(ポートフォワーディング)

ルーターの設定画面で、80番・443番ポートを、このWindows PCのローカルIPアドレスへ転送してください。
また、Windows側のファイアウォールでも80・443番ポートの受信を許可してください。

### (3) .env を設定する

`System_1` フォルダ直下に `.env.example` をコピーして `.env` を作り、`DOMAIN` を実際のドメイン名に
書き換えます(スキームは付けません)。

```
DOMAIN=your-domain.example.com
```

### (4) ベーシック認証を必ず設定する(重要)

**この設定をしないと、URLを知っている誰でもお子さんの映像・通知を見られる状態で
インターネットに公開されてしまいます。** 必ず設定してから公開してください。

```
docker run --rm caddy:2-alpine caddy hash-password --plaintext "設定したいパスワード"
```

で出力されたハッシュ文字列を `.env` に追記します。

```
BASIC_AUTH_USER=admin
BASIC_AUTH_HASH=(↑で出力された文字列)
```

さらに `client/Caddyfile` の以下のコメントを外します。

```
basicauth {
	{$BASIC_AUTH_USER} {$BASIC_AUTH_HASH}
}
```

### (5) 起動

```
docker compose down
docker compose up --build
```

ドメインへのアクセスが確認できると、Caddyが自動でLet's EncryptからHTTPS証明書を取得し、
以降は `https://your-domain.example.com` でアクセスできるようになります。

## 4. カメラ配信端末と閲覧専用端末について

このアプリはブラウザでページを開いた端末がWebカメラ映像を送る仕組みのため、インターネットに
公開すると「外出先からダッシュボードを見ようとした端末」まで自分のカメラを使おうとしてしまいます。

そこで、実際にお子さんの部屋を映す端末(このPC自身など)だけ

```
http://localhost/?capture=1
```

のようにURLの末尾へ `?capture=1` を付けてアクセスしてください(このPCから `localhost` で
アクセスする場合は付けなくても自動的にカメラが有効になります)。それ以外の端末で
`https://your-domain.example.com` のように開いた場合は、自動的に「閲覧専用モード」になり、
カメラへのアクセス要求は行われず、通知や3D表示の閲覧だけができます。

## 5. その他の注意点

- お子さんの映像を扱うシステムのため、公開する場合は上記のベーシック認証を必ず設定し、
  パスワードは推測されにくいものにしてください。
- サーバー用イメージにはPyTorch(CPU版)が含まれるため、イメージサイズは1.5〜2GB程度になります。
- このDocker構成は、開発環境(クラウドのサンドボックス環境)ではコンテナレジストリへの
  アクセス制限のため実際に `docker compose up` までは実行できておらず、設定ファイル自体の
  正しさ(Caddyの振り分けルール・環境変数の受け渡しなど)は個別に検証済みですが、
  実際のビルドはお客様の環境が初めてになります。もしビルド時にエラーが出た場合は、
  そのエラーメッセージを教えていただければ修正します。
